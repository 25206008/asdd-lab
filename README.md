A. Basic Agile concepts 
Q1. What is Agile? 
Agile is a software development approach in which we develop software in small parts instead 
of developing the entire project at once. 
We take feedback from the customer regularly and make improvements. This helps us deliver 
software faster and handle changing requirements. 
Example: Instead of developing an entire shopping website in one go, we first develop login, 
then product browsing, then payment, and so on. 
Q2. Why do we use Agile? 
We use Agile because: 
●  Requirements can change during development. 
●  We can deliver software in smaller parts. 
●  We receive regular customer feedback. 
●  Problems can be identified early. 
●  Team members can collaborate more easily. 
Q3. What are the main characteristics of Agile? 
The main characteristics are: 
1.  Iterative development – Software is developed in repeated cycles. 
2.  Incremental delivery – We deliver small working parts of the software. 
3.  Customer collaboration – We regularly take feedback from customers. 
4.  Flexibility – We can accept changing requirements. 
5.  Continuous improvement – We improve the product and process regularly. 
Q4. What is Scrum? 
Scrum is an Agile framework used to manage software development work. 
In Scrum, the team divides the project into small periods called Sprints. During each Sprint, the 
team completes selected tasks and delivers a working part of the software. 
Q5. What is a Sprint? 
A Sprint is a fixed period during which the development team works on selected tasks and tries 
to complete them. 
A Sprint usually lasts between one and four weeks. 
Example: A team may take a two-week Sprint to develop the login and registration features of a 
website.

The Scrum Master helps the team understand and follow Scrum practices. 
They conduct or facilitate Scrum events, help remove obstacles, and improve the team's

Q9. What is a Product Backlog? 
A Product Backlog is a list of all the features, improvements, bug fixes, and tasks that may be 
required in a product. 
It is arranged according to priority and is maintained by the Product Owner. 
Example: For a shopping website, the Product Backlog may contain: 
●  User registration 
●  User login 
●  Product search 
●  Add to cart 
●  Online payment 
●  Order tracking 
Q10. What is a Sprint Backlog? 
A Sprint Backlog is the collection of Product Backlog items selected for a particular Sprint, along 
with the plan for completing them. 
It is managed by the Developers. 
Example: From the shopping website's Product Backlog, the team may select login, registration, 
and password reset for the current Sprint.

Q14. What is an Epic in Agile? 
An Epic is a large feature or requirement that can be divided into smaller User Stories. 
Example: User Management is an Epic. It can contain user registration, login, password reset, 
and profile management stories. 
Q15. What are Story Points? 
Story Points are used to estimate the effort, complexity, and uncertainty involved in completing a 
User Story. 
They do not directly represent hours. 
Example: A simple login feature may receive 3 Story Points, while a complex payment 
integration may receive 8 Story Points. 
Q16. What is a Sprint Goal? 
A Sprint Goal is the main objective that the team wants to achieve during a Sprint. 
Example: The Sprint Goal can be to complete the user login and registration functionality. 
C. Sprint process 
Q17. Explain the Sprint process in an Agile team. 
The Sprint process generally follows these steps: 
1.  Sprint Planning: The team discusses the work to be completed and selects items from 
the Product Backlog. 
2.  Sprint Backlog Creation: Selected items and the plan to complete them form the Sprint 
Backlog. 
3.  Development: Developers work on the selected stories. 
4.  Daily Scrum: Team members discuss progress, the next steps, and any obstacles. 
5.  Sprint Review: The team presents the completed work and collects feedback. 
6.  Sprint Retrospective: The team discusses what went well, what did not go well, and how 
to improve. 
7.  Next Sprint: The team starts the next Sprint using the updated Product Backlog. 
Q18. What is Sprint Planning? 
Sprint Planning is a meeting conducted at the beginning of a Sprint. 
The team decides: 
●  Why the Sprint is valuable. 
●  What work can be completed. 
●  How the selected work will be done. 
Q19. What is Daily Scrum? 
Daily Scrum is a short daily meeting where Developers inspect progress towards the Sprint Goal 
and plan their work. 
It is commonly conducted for 15 minutes. 
Team members may discuss what they completed, what they plan to do next, and any 
obstacles.

B. CI/CD Pipeline 
Q99. What is CI/CD? 
CI/CD stands for Continuous Integration and Continuous Delivery or Continuous Deployment. 
It is a process used to automate the software development and release process. 
It helps developers frequently integrate code, test it automatically, and deliver or deploy 
software. 
Q100. What is Continuous Integration (CI)? 
Continuous Integration is the practice of frequently combining developers' code changes into a 
shared repository. 
After code is pushed, automated builds and tests are run to identify errors early. 
Example: Whenever a developer pushes code to GitHub, a workflow automatically checks 
whether the application builds successfully. 
Q101. What is Continuous Delivery? 
Continuous Delivery means that the software is automatically built and tested and kept ready for 
release. 
The final production release usually requires manual approval. 
Q102. What is Continuous Deployment? 
Continuous Deployment means that every code change that passes the required automated 
checks is automatically deployed to production. 
It does not require a separate manual approval for each release. 
Q104. What are the stages of a CI/CD Pipeline? 
A common CI/CD pipeline contains these stages: 
1

Developer writes code and pushes it to GitHub. 
2

The application is built and dependencies are prepared. 
3 
Test 
Automated tests check whether the application works. 
4 
Quality and Security Checks 
Code is checked for errors and security issues. 
5 
Package 
A deployable package or Docker image is created. 
6 
Deploy 
The application is deployed to a server or cloud platform. 
7 
Monitor 
The deployed application is monitored for problems. 
Q105. Why is CI/CD important? 
CI/CD is important because it: 
●  Reduces manual work. 
●  Detects errors early. 
●  Makes software releases faster. 
●  Improves software quality. 
●  Reduces human mistakes. 
●  Makes development and deployment more reliable. 
Q106. What is the difference between CI and CD? 
CI focuses on automatically integrating and testing code changes. 
CD focuses on preparing software for release or automatically deploying it. 
Q107. What is DevOps? 
DevOps is a combination of Development and Operations practices. 
It focuses on improving collaboration between developers and operations teams and automating 
the software development, testing, deployment, and monitoring process. 
Q108. Why do we use DevOps? 
We use DevOps to release software faster, improve collaboration, reduce manual work, identify 
problems early, and maintain reliable applications. 
Q109. What is the relationship between GitHub Actions and CI/CD?

Q177. What is Grafana? 
Grafana is an open-source monitoring and visualization platform used to display data through 
dashboards, graphs, charts, and alerts. 
Q178. Why do we use Grafana? 
We use Grafana to monitor systems and understand their performance. 
It helps us visualize information such as CPU usage, memory usage, network traffic, server 
health, and application performance. 
Q179. What is Monitoring in DevOps? 
Monitoring is the process of continuously observing an application's or system's performance 
and health. 
It helps us detect problems, understand system behaviour, and maintain availability. 
Q180. What is a Grafana Dashboard? 
A Dashboard is a visual page containing panels that display information about a system. 
A dashboard can contain graphs, tables, statistics, and other visual elements. 
Q181. What is a Panel in Grafana? 
A Panel is an individual visual component inside a Grafana Dashboard. 
For example, a dashboard may contain one panel showing CPU usage and another showing 
memory usage. 
Q182. What is a Data Source in Grafana? 
A Data Source is the system from which Grafana gets data for visualisation. 
Examples include Prometheus, InfluxDB, Elasticsearch, and supported SQL databases. 
Q183. What is Prometheus? 
Prometheus is an open-source monitoring and alerting system commonly used to collect and 
store numerical metrics. 
It can collect system and application performance data and make it available for queries. 
Easy way to remember: Prometheus collects and stores monitoring metrics. Grafana displays 
those metrics in dashboards. 
Q185. What are Metrics? 
Metrics are numerical measurements that show the performance or condition of a system. 
Examples include CPU usage, memory consumption, request count, and response time. 
Q186. What is Alerting in Grafana? 
Alerting is a feature that notifies users when specified conditions are met. 
For example, an alert can be configured to notify the team when CPU usage remains above a 
defined threshold.

Q191. What is Kubernetes? 
Kubernetes is an open-source container orchestration platform used to deploy, manage, and 
scale containerised applications. 
It automates tasks such as starting containers, replacing failed containers, managing application 
replicas, and distributing traffic. 
Q192. Why do we use Kubernetes? 
We use Kubernetes because managing many containers manually can become difficult. 
It helps us: 
●  Deploy containerised applications. 
●  Manage multiple containers. 
●  Scale applications. 
●  Recover from container failures. 
●  Distribute network traffic. 
●  Perform rolling updates. 
Q193. What is Container Orchestration? 
Container Orchestration means automatically managing containers across different machines. 
It includes deploying containers, managing their availability, scaling them, and handling 
communication between them. 
Q194. Why is Kubernetes called a container orchestration tool? 
Because it manages the complete lifecycle of containerised applications. 
It decides where application workloads should run, maintains the required number of running 
instances, and helps recover when failures occur. 
Q195. What is a Kubernetes Cluster? 
A Kubernetes Cluster is a group of machines that work together to run containerised 
applications. 
A cluster contains a Control Plane and one or more Worker Nodes. 
Q196. What is the Control Plane? 
The Control Plane manages the Kubernetes cluster. 
It makes decisions about scheduling workloads, monitoring the cluster, and maintaining the 
desired state of applications. 
Q197. What is a Worker Node? 
A Worker Node is a machine in a Kubernetes cluster where application workloads run. 
It contains the components required to run and manage Pods. 
Q198. What is a Pod? 
A Pod is the smallest deployable unit in Kubernetes. 
It contains one or more containers that share network resources and can share storage. 
Usually, one main application container runs inside a Pod. 
Q203. What are the types of Kubernetes Services? 
There are three commonly discussed Service types: 
1.  ClusterIP: Makes the application accessible inside the cluster. 
2.  NodePort: Exposes the application through a port on each eligible node. 
3.  LoadBalancer: Exposes the application through an external load balancer, when 
supported by the environment. 
Q221. What are the main components of the Kubernetes Control Plane? 
The main components are: 
1.  API Server: Entry point for communication with the Kubernetes cluster. 
2.  Scheduler: Selects a suitable Worker Node for newly created Pods. 
3.  Controller Manager: Runs controllers that help maintain the desired cluster state. 
4.  etcd: Stores cluster configuration and state information 
Q227. Is Kubernetes a replacement for Docker? 
No. They serve different purposes. 
Docker is commonly used to build container images, while Kubernetes manages containerised 
applications across a cluster. 
Modern Kubernetes clusters use compatible container runtimes such as containerd rather than 
requiring Docker Engine as the runtime. 
Q228. What is the relationship between Docker, Kubernetes, and CI/CD? 
Docker packages an application into a container image. 
CI/CD automates the process of building, testing, and delivering that image. 
Kubernetes deploys and manages the containerised application in a cluster.

The common DevOps lifecycle includes:

3.  Build 
4.  Test 
5.  Release 
6.  Deploy 
7.  Operate 
8.  Monitor 
These stages form a continuous cycle in which feedback from monitoring can be used to

improved.

features of a website.
